MathBank Desktop — Codex 개발 인계 프롬프트 (자동 처리·교사 확정 없는 최종 통합본)
아래 전체 내용을 개발 지시로 받아 실제 소스 분석, 구현, 빌드와 검증까지 진행해줘. 계획서나 화면 시안만 만들고 끝내지 마. 이 문서는 2026-10-29까지 확인한 모든 요구를 통합·보완한 것이며, 이후 내가 지시하는 변경을 우선한다.
1. 만들 프로그램과 작업 원칙
나는 수학 수업에 사용할 Windows 데스크톱 문제은행 프로그램을 원한다. 이름은 MathBank Desktop으로 한다. 핵심 흐름은 다음과 같다. PDF 등록 → 문항 자동 분리 → 원문 그대로 타이핑·수식·도형 재작성 → 자동 원본 대조·오류 재처리 → 빠른답·풀이 및 단원·난이도 → 학생별 시험지·과제 → 채점·성적표·오답 관리.
- 브라우저 주소를 열거나 BAT·터미널을 실행해야 하는 제품이 아니라, 설치 후 아이콘을 더블클릭하면 독립 데스크톱 창(Native Window)으로 즉시 열리는 Windows 프로그램(.exe)으로 만들어줘.
- 데스크톱 아키텍처 선택:
  - 수식(KaTeX/MathJax), 벡터 도형(SVG Canvas), A4 2페이지 성적표 및 시험지 조판(@page CSS)의 인쇄 품질과 데스크톱 파일 제어 안정성을 모두 확보하기 위해 PySide6 (Qt WebEngineView) 또는 PyWebView (Edge WebView2) 기반 네이티브 데스크톱 창 + 내장 로컬 코어 엔진 + PyInstaller 등으로 실행 프로그램 패키징 후 필요 시 Inno Setup으로 설치 프로그램 제작 구조를 권장한다. (프레임워크를 먼저 여러 개 구현하지 말고 수식·벡터·파일 접근·배포·출력을 시험하는 작은 실행 예제로 하나를 선택해라. 인쇄 품질이 깨지는 위젯 구성은 사용하지 마.)
  - PDF 저장 및 인쇄는 외부 브라우저 팝업을 띄우지 않고, 앱 안에서 A4 PDF 저장과 실제 프린터 출력을 각각 구현해야 한다. PDF 저장 API와 프린터 API를 구분하고, 수식·글꼴·도형 렌더링 완료를 기다린 후 출력한다. 출력 완료·실패를 비동기 결과로 확인하며 빈 파일을 성공으로 처리하지 않는다.
- Python·Node·개발 도구를 사용자가 따로 설치하지 않도록 런타임을 패키징해줘. AI 연결 등 외부 의존성이 있으면 앱 안에서 설치 여부와 필요한 조치를 안내해줘.
- 기존 웹페이지를 EXE로 감싸기만 하고 기존 오류와 복잡한 사용 흐름을 그대로 옮기지 마. 데스크톱 편집·저장·인쇄에 맞게 설계해줘.
- 반복 패치, 복수 실행 파일, 여러 복구 BAT를 사용자에게 던지는 방식은 끝낸다. 하나의 프로그램 안에서 연결·진단·재시도·백업·복원이 가능해야 한다.
- 작은 구현 단위로 실제 실행을 확인하며 진행하고, 정상 작동하는 기반 위에 기능을 늘린다. 디자인만 갖춘 미작동 버튼을 완성으로 보고하지 않는다.
- 모든 임의 PDF를 자동으로 100% 인식한다고 주장하지 마. 목표는 정확한 결과이며, 불확실하거나 틀린 결과를 감추어 확정하는 것은 금지한다. 자동 처리의 한계는 앱 안의 대조·수정·재검토 흐름으로 해결한다.
최우선 사용자 요구 — 교사 검증·확정 단계 제거
이 문서의 과거 버전보다 아래 요구가 우선한다.
- 모든 문항에 교사가 ‘원본 대조 완료’, ‘검증’, ‘확정’, ‘승인’을 눌러야 다음 단계로 넘어가는 흐름은 만들지 않는다. 해당 필수 버튼·체크박스·대기 상태를 제거한다.
- 사용자는 PDF를 등록하고 ‘자동 처리 시작’을 한 번 누르면 된다. 분리·전사·도형 재작성·독립 대조·답/풀이·분류까지 작업 큐가 이어서 실행한다. 완료한 문항은 즉시 보관함과 시험지 제작에서 사용한다.
- 수동 원문 편집·도형 수정·답/풀이 수정은 필요할 때만 쓰는 선택 기능이다. 사용자가 편집했다고 승인 버튼을 다시 요구하지 않는다. 변경된 부분과 그에 의존하는 결과만 자동 재검사한다.
- 교사 승인 대신 자동 검사를 구현한다. 검사 결과를 항상 통과시키거나 실패 플래그를 삭제하는 방식으로 승인 단계를 없애지 않는다.
- 오류가 감지되면 해당 문항만 확대 판독·영역 재분석·독립 재판독 등 서로 다른 방법으로 제한된 횟수 안에서 자동 재처리한다. 단순 동일 요청 반복은 피한다.
- 자동 복구가 끝내 실패하면 문항과 원본을 ‘처리 예외’에 보존한다. 다른 문항은 계속 진행한다. 원인·실행한 조치·재처리 버튼·선택적 수동 편집만 제공하며, 사용자에게 모든 문항의 검수를 떠넘기지 않는다.
- 자동 처리 완료는 정해진 자동 검사를 통과했다는 뜻이다. 절대적 무오류나 모든 PDF 100% 정확성을 뜻하는 문구를 제품에 표시하지 않는다.
- 예외가 있는 시험지를 출력할 때 해당 문항 목록과 사유를 한 번에 알려준다. 사용자가 모르게 누락하거나 대체하거나 원문 이미지를 끼워 넣지 않는다. 완료 문항으로만 만들기, 예외 재처리, 명확한 표시가 있는 초안 출력 중에서 선택할 수 있게 한다.
- 본 문서에 남아 있는 ‘기존 수동 수정·확정값 보호’는 과거에 저장한 수동 수정 데이터(user_modified)를 보호하라는 뜻이며 신규 필수 승인 절차를 만들라는 뜻이 아니다.
2. 먼저 기존 작업물을 조사하고 보존해줘
현재 폴더에서 소스 ZIP, 인계 문서, 성적표 샘플, 실제 운영 데이터 위치를 먼저 조사해줘. 압축파일 이름이나 버전 숫자만으로 최신·정확성을 판단하지 마.
참조할 수 있는 기존 작업물(폴더 내 실제 존재 여부를 먼저 확인할 것):
- MathBank_Studio_v3_7_2_SourceRead_Fix.zip, MathBank_Studio_v3_7_Final.zip, MathBank_Studio_v3_6_1_Fixed.zip 등 작업 폴더 내 존재하는 MathBank_Studio_*.zip 패키지들
- MathBank_230_Reclassify.zip 및 MathBank_Handoff.md: 별도로 진행된 분류·성적표 요구와 구현. 파일이 실제 제공되어 있는지 확인하고, 없다면 읽었다고 하지 마.
- Math_Report_mid.pdf, Math_Report_high.pdf, Math_Report_high.html, math_insight.html: 중등·고등 성적표의 기존 결과물·디자인 참고. 본 문서의 최신 요구와 충돌하는 오래된 문구·샘플은 되살리지 마.
- 기존 PC의 실제 data 폴더 전체 또는 MATHBANK_DATA로 지정한 경로: PDF·이미지·DB·학생·과제·채점 등 운영 자료. 배포 ZIP의 샘플 데이터와 구분한다.
각 자료의 실제 내용·해시·데이터 수·기능을 비교해 재사용할 부분을 결정해줘. 소스 ZIP만 옮긴 것으로 운영 기록까지 이전했다고 주장하지 마. DB만 복사하지 말고 연결된 PDF·이미지·첨부파일도 함께 이전한다. 원본을 직접 수정하지 않고 백업과 별도 개발 사본을 만든다. 기존 문항 ID, 출처, 학생, 반, 과제, 배부 기록, 채점, 성적표, 사용자 수동 수정값을 보존한다. 버전 간 데이터 구조가 다르면 명시적인 마이그레이션과 실패 시 복구를 구현한다. 데이터 개수와 관계뿐 아니라 원본 파일 해시도 대조한다. 로그인 토큰·API 키·개발 환경의 비밀정보는 배포물에 넣지 않는다.
기존 패키지에 관해 확인된 한계(반드시 주의할 것):
- 3.7.2 샘플 패키지의 1,323문항 중 6문항만 직접 원본 대조를 거쳤고 나머지 1,317문항은 원본 기반 재인식이 필요했다. 기존 6문항도 신규 자동 검사의 비교 사례일 뿐 전체 품질을 대표하지 않는다. 이는 그 패키지의 상태이며 현재 운영 DB의 상태로 일반화하지 마.
- 예전 전사·보기·도형·정답·해설에 템플릿 기반 임의 생성 내용이 섞여 있었던 이력이 있으므로, 검증되지 않은 임의 생성 텍스트나 도형을 자동 원문 대조 통과 상태로 위장하지 마. 백업·메타데이터에 남은 옛 임시 생성 내용을 검증된 정답·원문으로 되살리지 마.
- 이전 단위 테스트 통과 수는 실제 AI 인식 정확도나 Windows 실행 검증을 의미하지 않는다.
- 미완성 구독 연결 정리 브랜치가 제공되어도 완성품으로 간주하지 말고 인터페이스·의존성부터 확인한다.
3. PDF 등록과 문항 분리
텍스트 PDF와 스캔 PDF를 구분하고, 페이지·문단·열·문항 번호·보기·공통 지문·그림의 관계를 분석한다.
- 단일/다단 편집, 페이지를 넘는 문항, 공통 지문에 딸린 여러 문항, 소문항, 표, 그래프, 기하 도형을 처리한다.
- 머리말·꼬리말·페이지 번호·장식·해설·빠른정답표를 문제 본문으로 섞지 않는다. 문제/정답/해설의 역할을 분리하고 근거로 연결한다.
- 원본 PDF와 페이지, 영역 좌표, 여러 영역의 읽기 순서, 원래 문항 번호, 출처 해시를 저장한다. 시험지 인쇄용 새 번호(01, 02...)와 교재 원본 번호(0023 등)는 별도 관리한다.
- 자동 분리 결과를 원본 위에서 확인하고 마우스로 경계 이동, 영역 추가·제외, 문항 합치기·나누기·순서 변경을 할 수 있어야 한다.
- 문항 0개, 실제 빈 페이지, 경계 불명확, 파일 열기 실패, OCR 실패를 서로 다른 결과로 처리한다. 실패를 성공으로 기록하지 않는다.
- PDF 중복 등록과 중복 문항 후보를 감지하되 비슷한 변형문제를 자동 삭제하지 않는다.
- 한 페이지 오류로 나머지 자료를 잃지 않고 정상 결과를 보존해 이어서 처리한다. 암호·손상·지원 불가 파일은 원인과 사용자가 취할 조치를 보여준다.
4. 원문 타이핑·수식·도형
목표는 잘라 붙인 문제 이미지가 아니라 한글·Word에서 편집한 것처럼 일관된 글꼴·수식·도형으로 구성된 문제다.
- 일반 본문은 편집 가능한 텍스트, 수식은 구조화된 LaTeX($...$, $$...$$), <보기>(ㄱ, ㄴ, ㄷ)·표·소문항·객관식 5지선다(①~⑤)는 별도 구조로 저장한다. 화면에 보이는 수식/도형 미리보기와 원문 편집기를 함께 제공한다.
- 원본의 숫자, 부호, 지수, 첨자, 절댓값, 분수, 구간, 조건, 한글 표현, 보기 순서를 그대로 옮긴다. 원문에 없는 설명을 덧붙이거나 수학적으로 비슷한 다른 문제로 바꾸지 않는다.
- 이전 저장 텍스트·정답·단원·교재명·문항번호로 원문을 추측하거나 지어내지 않는다. 새 전사는 반드시 실제 PDF 영역 또는 고해상도 원본 크롭 영상에서 출발한다.
- 도형은 SVG 등 벡터와 편집 가능한 구조화 도형 객체(좌표평면, 점·선·다각형, 원과 직선, 함수 그래프, 벤다이어그램, 수직선 등)로 재작성한다. 점·선·곡선·호·좌표축·각·기호·라벨·길이·표식의 관계를 보존하고 텍스트와 겹치지 않게 한다.
- 원문에 없는 길이·좌표·직각·평행 관계를 추가하지 않는다. 축척을 알 수 없는 그림을 정확한 실측 도형인 것처럼 처리하지 않는다.
- 복잡한 도형을 벡터로 재구성하지 못하면 임의 도형으로 대신하지 말고 재구성 방법을 바꿔 자동 재시도한다. 끝내 실패하면 해당 문항만 처리 예외(diagram_reconstruction_failed)로 보존한다. 원본 이미지는 대조용으로 보존하며 순수 타이핑 출력에서 몰래 대체하지 않는다. (단, 사용자가 예외 알림에서 명시적으로 선택한 경우에 한해 본문·수식·보기는 타이핑을 유지하고 도형 영역만 배경 보정 크롭으로 삽입하거나 도형 편집기에서 수정 후 출력하는 옵션을 제공할 수 있다.)
- 원본 크롭 이미지와 타이핑+벡터도형 결과를 좌우로 나란히 비교(Side-by-Side Diff View)하고 확대·이동·도형 수정·문구 수정·저장·재검토를 앱 안에서 즉시 할 수 있어야 한다.
- 자동 대조는 숫자·부호·조건·보기·도형 관계를 확인한다. 단순 문자열 일치나 AI 두 번의 동의만으로 완전 정확성을 보장했다고 주장하지 않는다.
- 문항 상태는 선형 5단계 승인이 아니라 독립 필드로 관리한다: 영역분리, 본문전사, 도형재작성, 원문자동대조, 정답검증, 풀이검증, 분류 각각에 미처리/진행/통과/예외와 입력 버전을 기록한다. 교사확정 상태는 신규 흐름에 없다. 전사 완료가 정답·풀이 검증 완료라는 뜻이 아니다. 문제지 출력에는 원문·도형 자동대조 결과를, 정답·해설지에는 해당 정답·풀이 검사 결과까지 적용한다.
- 원본·영역 또는 본문·도형을 바꾸면 관련 자동 검사 결과만 무효화하고 새 입력 버전으로 재처리한다. 원본 해시·영역·본문·도형·설정 버전이 일치하는 결과만 저장하며 늦게 도착한 옛 작업은 덮어쓰지 못하게 한다. 사용자가 직접 수동 수정한 값(user_modified)을 백그라운드 일괄 작업이 덮어쓰지 않는다.
- 자동 검사 통과 문항은 별도 승인 없이 순수 타이핑 문제지에 바로 사용할 수 있다. 처리 예외는 별도 표시하고 초안 출력에 포함할 경우 문항별 예외를 명시한다. 정답·풀이가 실패한 경우에도 원문 검사에 통과한 문제 본문까지 무조건 사용 불가로 만들지 않는다.
- 반드시 회귀 테스트 사례로 포함할 기존 오류:
  - 원본은 y=|x+1|-|x-2|, 직선 mx-y+3m-4=0인데 예전 전사는 y=|x+1|-|x-1|, mx-y+3m-2=0으로 바뀌었다. 이 같은 숫자·상수 변경을 놓치지 않아야 한다. 문항 번호(1079 등)를 하드코딩해 통과시키지 말고 공통 판독·대조 과정을 수정한다.
5. 빠른답·풀이와 검증 (과목 교육과정 범위 및 난이도 맞춤 해설)
- 정확히 판독된 문제를 대상으로 빠른답과 단계별 풀이를 생성한다. 원문에 공식 답·해설이 있으면 출처를 연결하고 AI 풀이와 구분한다.
- 상세 해설 품질 및 교육과정 준수 원칙:
  - 단순한 접근법 요약 한두 줄로 끝내지 말고, 해당 학년 학생에게 필요한 조건 해석, 식을 세운 이유, 핵심 변형과 최종 계산을 단계별로 작성한다. 논리적 비약과 결정적 계산 생략을 피하되 단순 연산까지 불필요하게 늘어놓지는 않는다.
  - 선행 개념 사용 금지: 반드시 해당 문항의 학교급·과목 교육과정 범위 내의 개념과 공식만 사용해 풀이한다(예: 중1 문제에 연립방정식·이차방정식 사용 금지, 고1 공통수학1·2 문제에 미분·로피탈의 정리·벡터 사용 금지).
- 객관식 선택지 번호(①~⑤)와 실제 답 값, 주관식의 동치 표현·정의역·단위·조건·경우 누락을 검토한다. 모든 LaTeX 수식 구분자($...$)의 짝이 맞는지 검증한다.
- 가능한 계산은 수식 연산(SymPy 등)·대입·수치 확인 등 적절한 도구로 검산하고, 도구 검산이 적용되지 않는 기하·논증은 별도로 검토한다. 도구 실행 자체를 수학적 정당성의 증명으로 간주하지 않는다.
- 답안 충돌, 해 없음·복수 해, 조건 모순, 판독 불확실성을 숨기지 않는다. 원문을 바꾸어 답을 맞추지 않는다.
- 사용자가 필요할 때 답·풀이를 직접 수정할 수 있고 수정 이력을 보존한다. 필수 확정 버튼은 두지 않고 관련 검사를 자동 실행한다. 이미 저장된 풀이가 있으면 검토 단계부터 재개할 수 있게 한다.
- 문항 전체를 다시 풀거나 사용자 수동 수정본(user_modified)까지 덮어쓰며 재생성하는 작업은 별도 범위 선택과 명시적 실행으로 제공한다.
6. 단원·난이도 분류 (과정 범위와 사고 수준 기준)
이전 인계 문서의 분류 요구와 과정 고정 원칙을 함께 유지한다.
- 기존 77개 주제 ID와 분류표가 제공되면 확인하여 재사용한다. 임의로 새 77개 목록을 만들지 않는다. 주단원 하나, 보조 단원 최대 3개, 교재 인쇄 단원명을 분리한다.
- 교재 과정 고정(Course-Scope Lock) 원칙:
  - 내용과 실제 풀이에 따라 주단원을 판단하되, 교재나 시험지의 과정(예: 고쟁이 공통수학2, 쎈 공통수학2, 대수, 미적분Ⅰ 등)이 지정된 경우 문제 본문에 ‘일차함수’, ‘이차함수’, ‘피타고라스 정리’ 등 하위 학년 기초 용어가 등장하더라도 주단원은 지정 과정 안에서 분류하고 하위 학년 개념은 선수개념 태그로 별도 저장한다. 단, 지정 과정과 실제 내용이 충돌하면 억지로 단원을 찍지 않고 과정 불일치 표시와 자동 재판정을 수행한다. 교재별 설정은 기본값이며 문항별 과정 수정이 가능해야 한다. 잘못 지정한 교재 설정을 자동 원문 판독의 근거로 삼지 않는다.
  - 반대로 교재명·페이지·문항 번호 숫자만으로 내용을 무시하고 기계적으로 단원을 찍지 않는다.
- 처리한 문항의 난이도는 Lv.1 ~ Lv.5 중 하나를 저장하며 난이도 보류값은 사용하지 않는다. 신뢰도와 판독·검증 상태는 별개다.
  - Lv.1: 정의·공식 직접 적용 (기초 연산·개념 확인).
  - Lv.2: 정형 유형 인식과 익숙한 절차 선택.
  - Lv.3: 조건 재구성, 표준 치환·표현 전환·경우 분류.
  - Lv.4: 드러나지 않은 결정적 관찰 또는 비정형 조건 조직이 필수.
  - Lv.5: 핵심 관찰 이후 추가 비정형 추론 또는 깊은 다단계 논증이 필수. 단일 개념에서도 가능.
- 과정별 기준 문항집: 고1·고2 학력평가 및 고3·수능 문항을 난이도 비교 사례로 활용할 수 있다. 다만 연도·시험·과정·원문·실제 풀이와 판정 근거를 포함한 기준 문항집으로 관리한다. 20·21·29·30번 등 문항 위치나 배점만으로 Lv.5를 자동 부여하지 않는다. ‘킬러’라는 명칭 대신 해당 과정을 배운 학생에게 필요한 사고 수준으로 판단한다. 기준 자료가 제공되지 않았다면 있다고 가정하지 않는다.
- 계산량·개념 수·풀이 길이·A/B/C 표기만으로 레벨을 올리거나 임의 가중 평균을 쓰지 않는다.
- 주단원 근거, 풀이 경로, 결정적 판단, 인접 레벨과의 차이, 신뢰도를 보여준다.
- AI 실패 시 기존의 유효한 분류·근거를 우선 보존한다. 근거가 전혀 없으면 이전 요구에 따라 수학 종합 / Lv.3 대체값을 저장하되 낮은 신뢰도와 대체 분류임을 표시한다. 이를 실제 판독 성공으로 취급하거나 미검토 문제를 출력 가능하게 만드는 근거로 쓰지 않는다.
- 전체/교재별/선택 문항 재분류, 변경 이력, 백업·재개를 지원한다. 과거 수동 확정값과 현재 수동 수정값의 재평가는 별도 선택한다. 새 필수 승인 단계를 만들지 않는다.
- 재분류만으로 원문·정답 검증 상태나 사용자 수동 수정본, 과거 시험·성적표의 스냅샷을 바꾸지 않는다.
7. 보관함·시험지·과제지 (대량 문항 렉 방지 및 DOCX 수식 내보내기)
- 대량 문항 조회 시 프리징(렉) 원천 방지:
  - 보관함에 수백~수천 문항이 있을 때 전체 문항을 한 화면에 동시에 렌더링하면 렉이 걸리므로, 기본 화면은 교재별·단원별·난이도별 요약으로 시작하되 필터 없는 ‘전체 보기’도 페이지 단위로 지원한다. 필터를 강제하는 것으로 조회 성능 문제를 숨기지 않는다. 목록 API는 페이지 단위 조회·정렬·총개수를 지원하고 원문 이미지·수식 렌더링은 필요한 항목만 불러온다.
  - 필터 선택 후에도 페이지네이션(예: 페이지당 50문항) 또는 가상 스크롤(Virtual List)을 적용해 스크롤과 수식 렌더링이 즉시 반응하도록 한다.
- 출처·교재·학교급·학년·단원·난이도·문항 유형·자동 검사 상태(통과/예외)·즐겨찾기로 검색·필터링한다. 자동 검증 통과 필드와 추정/예외 필드를 구분한다.
- 수동 선택과 단원·난이도·문항 수 조건으로 시험지·과제지를 구성한다. 조건에 맞는 문제가 부족하면 조용히 다른 문제로 채우지 않고 부족한 수량을 명확히 알린다.
- 순서·번호·배점·풀이 여백·글자 크기·단 수(A4 2단 시험지형 / 4분할 그리드형 / 1단 서술형)·페이지 나눔·제목·학원명·학생명·제출일 등을 설정한다.
- 문제지, 빠른답 표, 상세 해설지를 분리 출력한다. 학생용 문제지에 답과 교사용 메모가 섞이지 않게 한다.
- PDF 인쇄 및 편집 가능한 DOCX 내보내기:
  - DOCX 내보내기 시 수식은 단순 텍스트($x^2$)나 통짜 이미지가 아니라 latex2mathml + mathml2omml(또는 MML2OMML XSLT 변환)을 통해 MS Word 네이티브 수식 객체(<m:oMath> / OMML)로 삽입하여 Word에서 편집 가능한 수식으로 구현한다. 한컴오피스 한글의 가져오기·수식 편집은 별도 호환성 항목으로 실제 버전에서 시험하고 지원 범위를 기록한다. 변환하지 못한 수식은 위치와 원인을 보고하며 몰래 이미지·일반 텍스트로 대체하지 않는다.
  - 도형 또한 벡터(SVG 등) 품질을 유지한다. 벡터의 선명도와 Word·한글에서 점·선·라벨 각각을 편집할 수 있는지는 다른 요건이므로 지원 여부를 구분한다. 앱 안에서는 구조화 도형을 편집할 수 있어야 한다. 전 문항을 한 장의 캡처 이미지로 넣는 방식은 타이핑 내보내기로 취급하지 않는다.
  - 한컴오피스 한글에서의 활용은 생성된 DOCX 파일을 한글에서 불러와 수식·표·도형이 깨지지 않는지 실제 지원 경로를 검증해 안내한다. HWP/HWPX 직접 출력을 검증 없이 지원한다고 표시하지 않는다.
- 공통 지문·`<보기>` 박스·수식·도형·객관식 선지가 페이지나 단 경계에서 어색하게 잘리거나 분리되지 않아야 한다(페이지보다 긴 문항은 지문·소문항·풀이 단위로 안전하게 나누고 표 제목·공통 조건을 필요한 위치에 반복한다. 단순 break-inside: avoid만으로 해결되었다고 하지 않는다). A4 실물 크기에서 미리보기와 출력 결과를 확인한다.
- 저장된 시험지는 생성 당시의 문항 내용·정답·배점·순서·분류 버전을 스냅샷으로 보존해 이후 문제은행 수정으로 과거 시험지가 달라지지 않게 한다.
8. 학생별 과제 안내·배부·오답
- 학생·반·학교급(중등/고등)·학년·교사 메모와 학생별 시험·과제 폴더를 관리한다. 기존 데이터 모델에 필요한 항목부터 적용한다.
- 학생/반별 과제 배정, 기간·제출일·개별 안내문·제출/채점 상태·배부 이력을 제공한다.
- 학생마다 다른 문항 구성과 오답·취약 단원 기반 맞춤 클리닉 과제를 만들 수 있어야 한다. 같은 시험지의 재사용도 가능해야 한다.
- 학생별 PDF·안내문 생성, 일괄 내보내기·인쇄를 기본 배부 수단으로 구현한다. 로컬 EXE만으로 외부 접속 링크·자동 온라인 배부가 가능한 것처럼 꾸미지 않는다.
- 이메일·메신저·학생 포털 직접 전송은 별도 연동이 필요한 확장 기능이다. 연동 시 수신자·내용·첨부를 미리보기하고 사용자가 전송을 눌러야 한다. 개발 과정에서 실제 학생·학부모에게 시험 발송하지 않는다.
- 정오답(O/`X`)·미응답(—)·미채점·필요한 부분점수와 선택적인 오답 원인을 기록하고, 학생별 오답노트·단원별 기록을 연결한다.
- 오답 보완 과제와 유사문항 추천을 제공한다. 새 변형문항(숫자변형·사고변형) 생성은 원문 전사와 분리하고 정답·조건 검증을 거쳐야 한다. 오류가 있는 변형문항을 자동 배부하지 않는다.
9. 성적표 — 기존 확정 요구 및 중·고등 디자인 엄격 적용
기존 MathBank_Handoff.md의 요구를 유지하고 Math_Report_mid.pdf(중등), Math_Report_high.pdf(고등)가 실제 제공되면 디자인을 비교해 반영한다. 제공되지 않은 PDF의 내용을 이미 확인했다고 주장하지 않는다. 파일이 실제 존재하는지 먼저 확인하고, 없으면 읽었다고 주장하지 않는다.
- 저장 과제·시험의 학생별 ‘채점 · 성적표’에서 사용한다. 기본적으로 한 번 응시한 실제 결과를 바탕으로 작성한다.
- 중등용(MIDDLE SCHOOL REPORT)과 고등용(HIGH SCHOOL REPORT)을 분리한다. 실제 점수와 예상 점수를 구분하고, 고등 예상등급은 교사가 직접 입력·수정할 수 있도록 한다. 실제 참고 자료 없이 AI가 학교 등급·백분위를 임의로 단정하지 않는다.
- 기존 예상 점수 산식이 있으면 확인·보존한다. 산식이 없으면 임의 수식을 숨겨 넣지 말고 명시적인 기준을 설계해 검토 가능하게 한다. 학교시험 실측 예측과 단순 배점 환산을 혼동하지 않는다.
- 평가 범위·평가일·문항별 결과·총점·단원/난이도별 성취도 매트릭스를 실제 데이터와 연결한다. 미채점과 오답은 다르며 미채점을 자동으로 틀렸다고 처리하지 않는다.
- 점수 카드와 문제 번호 배지는 작고 단정하게, 서술형 분석 부분은 읽기 쉽게 기본 2페이지 A4 레이아웃으로 구성한다. 내용이 넘치면 글자를 과도하게 줄이거나 잘라내지 말고 페이지를 확장한다. A4 출력 기준으로 지나치게 작은 글씨·잘림·겹침을 피한다.
- ‘01 / 부족한 점과 보완 방법’: 어떤 문항·조건·개념에서 부족했는지([문제 진단])와 구체적인 실천 과제([연습])를 항목별로 중복 없이 구체적으로 쓴다. 정오답만으로 알 수 없는 오답 원인은 단정하지 않는다.
- ‘02 / 잘한 점과 강점’: 실제 해결한 문항과 사고 과정을 근거로 작성한다. 제목에 ‘칭찬’이라는 단어를 사용하지 않는다.
- ‘TEACHER'S NOTE / 총평’: 시험지의 구성·수준과 학생의 현재 상태를 학부모와 학생이 읽고 실질적인 학습 정보로 인식할 수 있을 만큼 고품질로 작성한다. 모든 학생에게 똑같은 상투적 빈 문구를 반복해 넣지 않는다.
- 삭제/금지 항목 엄수:
  - 다음 목표, 점수 목표, 같은 문항 재풀이 항목은 삭제 상태를 유지한다. (오답 보완 과제 생성 기능 자체와 성적표 내 삭제 항목을 혼동하지 않는다.)
  - 취약 단원을 확인하고, 새 조건에 적용합니다, 정확하게 해결한 문항에서 강점을 찾습니다 같은 기계적 부제는 다시 넣지 않는다.
  - 예상 점수 카드에 가상 데이터 안내 등 장황한 변명 문구를 되살리지 않는다. 필요한 산정 기준은 간결하게 별도 설명한다.
- 교사가 분석·보완 방법·강점·총평을 화면에서 직접 수정하고 저장·PDF 출력할 수 있어야 한다. 가상의 학생·점수는 테스트 데이터에서만 사용한다.
- 이미 확정한 채점·성적표 스냅샷은 문제은행 재분류·정답 수정으로 자동 변경하지 않는다. 다시 생성은 별도 행동으로 제공한다.
10. AI 이용과 비용 제약 (구독형 CLI 및 다중 공급자 선택 지원)
나는 기본적으로 ChatGPT Plus 구독 범위 내(Codex CLI) 사용을 원하며, 내 동의 없이 유료 API 과금이 자동 발생하는 구성을 원하지 않는다. 선택적 Gemini / OpenAI / Anthropic API 연결은 확장 가능한 공급자 인터페이스로 분리한다. 기본 구독 경로와 핵심 기능을 먼저 완성하고, API를 제공할 때는 사용자가 직접 공급자를 켜고 별도 과금에 동의한 경우에만 호출한다. API가 반드시 더 정확하다고 가정하지 않는다.
- API 키 입력을 필수로 강제하거나 유료 API로 몰래 자동 전환하지 않는다. Codex 개발 도구를 쓰는 것과 배포 프로그램에서 AI를 호출하는 구조를 구분한다.
- 구독 연결 구현 규칙:
  - 구현 시점 공식 문서를 확인해 구독 인증·이미지 입력·비대화형 실행·사용 한도·지원 OS와 배포 제약을 검증한다. 아래 명령은 시작 예시일 뿐 설치 버전의 실제 도움말과 문서에 맞춰야 한다. 구독이 무제한 호출이나 모든 작업의 지원을 뜻한다고 가정하지 않는다.
  - 앱에서 Codex CLI 구독 연결을 사용할 때는 대화형 프롬프트 대기로 멈추지 않도록 비대화형 실행(codex exec --ephemeral --skip-git-repo-check --sandbox read-only --image <img_path> --output-last-message <out_path> -)과 타임아웃, 취소, 프로세스 트리 종료, 독립 작업 폴더, 구조화 출력 스키마를 구현한다. 셸 문자열 조합 대신 인자 배열로 실행하고 공백·한글 경로를 검사한다. AI에는 필요한 원본 영역만 전달하며 개발 폴더·운영 DB 전체를 탐색할 권한을 주지 않는다.
  - 적응형 배칭: 여러 문항을 묶어 처리하는 방식은 단건 처리와 정확도·소요 시간·사용량을 비교한 후 적용한다. 문항별 ID·원본 영역·결과를 정확히 연결하고 누락·중복·다른 문항과의 혼합을 검사한다. 작은 수식이나 복잡한 도형 때문에 판독 품질이 떨어지면 단건 고해상도 처리로 전환한다. 배칭 여부와 관계없이 모든 문항에 독립 원본 대조를 적용하며, 묶음 호출만으로 구독 사용량이 줄어든다고 가정하지 않는다.
  - 설치·로그인 상태 확인(codex login 안내)·실제 이미지 판독 연결 시험·연결 해제 상태를 앱 설정 화면에서 관리한다.
- 선택적 외부 API(Gemini / GPT / Claude) 및 캐시 최적화:
  - 사용자가 설정 화면에서 직접 API 키를 입력하고 공급자(Claude, Gemini, OpenAI)를 선택한 경우에만 해당 API를 호출한다.
  - 동일한 문항 이미지와 프롬프트에 대해 중복 토큰이 소모되지 않도록 콘텐츠 해시 기반 응답 캐시를 적용한다. 키에는 원본·영역·전송 이미지 해시, 작업 종류, 공급자·모델, 프롬프트·스키마 버전, 입력 옵션을 포함한다. 예외·불완전 결과를 성공 캐시로 보관하지 않는다. 전사와 독립 재판독은 서로 다른 작업이며 최초 전사 캐시를 독립 재판독 응답으로 재사용하지 않는다. 해상도 최적화는 작은 지수·첨자·부호 보존을 실제 확인하고, 불명확하면 고해상도로 재시도한다.
- API 방식으로 로그인된 상태를 구독 연결 성공으로 표시하거나, 개발 PC의 인증 파일(secrets.json, .codex 토큰 등)을 배포물에 절대 포함하지 않는다. 비공식 세션 탈취·브라우저 무단 자동화를 사용하지 않는다.
- 한도·네트워크·인증 오류는 원인을 명확히 보여주고 작업을 일시정지·재개한다. 무한 재시도·숨은 과금·이미 정상 완료된 문제 전체의 재처리를 금지한다.
- 공식 구독 연결이나 API 호출이 불가능한 오프라인 환경에서는 원본 이미지+요청 패키지 내보내기(Export)와 결과 파일 가져오기(Import) 같은 수동 연결 경로를 제공한다. AI 응답 파일은 실행 코드로 취급하지 않고 스키마·크기·참조 무결성을 검사한다. HTML·SVG도 허용 요소만 사용하며 스크립트·외부 자원 호출을 차단한다. 가져온 결과는 문항 ID·원본 해시·버전을 검사한다.
- 로컬 OCR 모델을 보조로 지원한다면 실제 수학·한글·도형 판독 품질을 시험한다. 품질이 낮은 OCR 결과를 성공한 LaTeX 인식처럼 포장해 보여주지 않는다.
- 파일 보관·검색·교사 수동 편집·저장된 시험지 및 성적표 인쇄 등 AI가 필요 없는 기능은 AI 연결이 없어도 100% 동작하게 한다.
11. 안정성·사용 흐름
- 주요 화면은 ① PDF 자료실/분리 스튜디오, ② 문제 보관함/원본 대조 검토, ③ 시험지·과제 제작, ④ 학생·채점·성적표, ⑤ 작업 큐 센터, ⑥ AI·백업 설정으로 깔끔하게 정리한다. 비슷한 버튼과 유지보수 기능의 중복을 줄인다.
- 긴 작업(PDF 전체 분리, 일괄 전사·대조, 일괄 재분류·해설 생성)은 화면을 멈추지 않는 비동기 작업 큐(Background Job Queue)에서 실행한다. 문항별 상태·진행률·오류 사유·재시도·취소·중단 후 재개를 지원하고 작은 묶음(페이지 또는 문항 단위)으로 즉시 커밋·저장한다.
- 외부 AI 응답을 기다리는 동안 SQLite DB 쓰기 잠금(Lock)을 잡고 있지 않는다(DB 조회 → 락 해제 후 AI 호출 → 짧은 트랜잭션으로 결과 저장). 동시 편집·중복 클릭·앱 종료·예외가 자료 손실로 이어지지 않게 한다.
- 프로그램 설치 위치(읽기 전용 가능)와 운영 데이터 위치(%LOCALAPPDATA%\MathBankDesktop 또는 사용자 지정 MATHBANK_DATA 폴더)를 분리한다. 공백·한글 경로, 일반 사용자 권한, 네트워크 단절을 다룬다.
- 자동 백업·백업 ZIP 내보내기·검증 후 복원·업데이트 실패 시 자동 롤백을 제공한다. 앱 삭제·업데이트로 운영 데이터가 사라지지 않게 한다.
- 실제 사용하는 Windows 10 / 11 (64-bit) 환경을 기준으로 지원 범위를 정하고 그 환경에서 검증한다.
- 로그는 앱 안에서 열거나 내보낼 수 있고 API 키·비밀정보·학생 민감정보가 노출되지 않아야 한다. 문항 인식에는 학생 이름·연락처·성적을 보내지 않는다. 성적표 분석에 외부 AI를 쓸 때는 가명 ID와 필요한 평가 내용만 전달한다. 선택적 API 키는 OS 자격 증명 저장소 등 적절한 방식으로 보관한다.
- 백업은 SQLite의 일관된 스냅샷과 연결된 원본·첨부 목록을 묶어 생성한다. DB가 열린 상태에서 DB 파일 하나만 단순 복사해 완료로 처리하지 않는다. 복원 전 무결성·참조 파일·버전을 검사하고 실패 시 현재 데이터를 보존한다.
- 내장 웹 엔진을 쓰더라도 불필요한 외부 페이지 이동과 파일·프로세스 접근을 제한한다. 로컬 HTTP 서버가 필요하면 루프백만 바인딩하고 요청 인증·출처 검사를 적용한다.
12. 구현 순서와 완료 기준
먼저 기존 소스·운영 데이터·요구 대응표와 데스크톱 프레임워크 선택 이유를 짧게 정리한 뒤 구현을 바로 진행해줘. 매 단계마다 계획 승인만 반복 요청하지 마. 필요한 자료가 없으면 독립적으로 가능한 작업은 먼저 구현하고, 자료가 필요한 부분을 구체적으로 구분해줘.
진행 순서
1. 데이터 백업·마이그레이션과 독립 데스크톱 창(.exe) 실행 기반 구축.
2. 실제 PDF 등록 → 영역 분리·마우스 편집 → 원문 전사·벡터 도형 → 자동 원본 대조·예외 재처리·저장 → 재시작 후 복원까지 수직 연결.
3. 빠른답·단계별 수식 풀이(교육과정 범위 준수) 검증과 단원(과정 고정 Lock)·난이도(Lv.1~5) 분류.
4. A4 시험지·과제지 PDF 인쇄 및 편집 가능한 수식(OMML) 기반 DOCX 내보내기.
5. 학생별 배정·채점·기존 요구에 맞춘 중/고등 기본 2페이지 성적표·오답 클리닉 관리.
6. Windows 배포물(.exe / 설치 폴더) 제작 및 설치·업데이트·복원 검증.
검증 및 보고 기준
검증은 코드 단위 테스트와 실제 자료 대조를 분리해 기록한다.
- 대표 PDF 세트에 텍스트/스캔, 다단, 페이지 연결, 공통 지문, 표·복잡한 수식·도형을 포함한다. 실제 파일이 없으면 테스트용 생성 자료임을 명시한다.
- 문항 누락·중복·순서·숫자·부호·조건·선택지·도형 관계를 원본과 대조하고, 실패 사례(특히 1079번 y=|x+1|-|x-2| 상수 변질 사례 등)를 회귀 테스트로 남긴다.
- 자동 정확도 수치에는 대상 파일·문항 수·검사 범위·실패 수·교사 수정 필요 수를 함께 적는다. 모의(Mock) AI 응답 테스트 통과를 실제 AI 판독 정확도라고 주장하지 않는다.
- 원문을 읽지 못한 사례를 성공 결과로 보존하거나 출력에 섞는지 확인한다. 정상 사례와 오류 사례를 모두 검사한다.
- 실제 Windows 환경에서 설치 → 더블클릭 실행 → PDF 열기 → 인식·자동대조·자동재처리 → 교사 승인 없이 저장 → 재시작 → 시험지 PDF/DOCX 출력 → 채점 → 중/고등 성적표 출력 → 백업·복원 전체 흐름을 실행한다.
- 한글 경로, 설치 경로 변경, AI 한도·인증 실패·네트워크 단절, 중도 종료·재개, 기존 자료 업데이트 보존을 확인한다.
- 실제 렌더링한 시험지·성적표 PDF와 DOCX를 열어 수식·도형·글꼴·페이지 잘림을 눈으로 확인한다. 코드가 예외 없이 끝난 것만으로 출력 검증을 대신하지 않는다.
- Windows용 빌드는 Windows 빌드 환경에서 수행한다. Linux에서 Windows 실행 파일을 빌드·실행했다고 주장하지 않는다. 필요하면 Windows 빌드 스크립트와 CI 구성을 제공하되 이는 보조 자료다. 실제 빌드 산출물이 없거나 Windows 실행을 확인하지 못했으면 그 단계는 미완료로 보고한다. 빌드 성공과 실제 설치·실행·인쇄 검증을 구분한다. 사용자의 명시적 승인 없이 비공개 소스·학생 데이터를 외부 저장소에 업로드하지 않는다.
반드시 추가할 자동화·수용 검사
- 필수 교사 검증·확정 버튼 없이 PDF 한 개를 등록해 문항 분리부터 시험지 제작 가능한 상태까지 도달하는 전체 흐름을 검사한다.
- 정상 문항·본문 오독·도형 실패·풀이 실패를 섞은 자료에서 정상 문항은 계속 완료되고 예외만 별도로 남는지 확인한다. 실패 결과가 정상 결과처럼 출력되지 않아야 한다.
- 자동 재시도 횟수·이유·변경된 방법을 기록하고 최대 횟수 후 정지한다. 일시적 오류 재시도와 같은 틀린 결과의 반복 생성을 구분한다.
- 독립 재판독이 실제 별도 원본 판독을 수행했는지, 캐시 때문에 첫 응답과 같아진 것은 아닌지 검사한다.
- 수동 편집 직후 옛 AI 작업이 도착하는 경우 최신 문항을 덮어쓰지 않는지 검사한다.
- 사용자 PC에 Python·Node가 설치되지 않은 일반 계정에서도 배포물이 실행되는지 확인한다. WebView2 등을 쓰면 설치 감지와 필요한 런타임 배포 경로를 시험한다.
- 시험지·성적표·DOCX에서 누락된 수식, 빈 도형, 미출력 글꼴, 정답 노출, 긴 문항 잘림을 확인한다.
- 대표 실제 문항에 대해 원문 전사 정확도, 도형 관계 정확도, 답 정확도, 풀이 타당성, 분류 일치도를 각각 기록한다. 예외를 제외한 성공률만 제시하지 말고 전체 입력 중 자동 완료율과 예외율도 제시한다.
- 이번 작업에서는 기본 구독 연결을 통한 실제 이미지 입력부터 저장까지 확인한다. 실제 호출이 불가능하면 모의 응답 결과와 명확히 구분하고 AI 연동은 미검증으로 보고한다.
- 필요한 계획·중간 문서를 작성한 뒤 구현을 계속한다. 해결 가능한 오류를 사용자에게 패치 요청으로 넘기지 말고 직접 수정·재검사한다. 완료하지 못한 기능을 숨기거나 다른 결과물로 대체하지 않는다.
